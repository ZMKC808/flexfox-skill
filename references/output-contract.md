# 交付合同

完整写稿按需交付下列资产；未完成或免除的项明确标注原因，不伪造通过状态。

| 文件 | 必须性 | 内容与用途 |
|---|---|---|
| `brief.md` | 必须 | 一句话主线、素材关系与关键证据、读者带走的判断、图片计划、确认依据 |
| `evidence.md` | 必须 | 带 `E01`/`S01` 编号的已核验事实、核心数据、实操步骤、推断 |
| `sources/index.json` | 二创任务必需 | 所有输入链接的 `S01` 编号、抓取状态、路径与图片数；失败来源不可静默忽略 |
| `outline.md` | 必须 | 内部写作大纲：3–5 个章节、关键事实编号、展开路径、段落预算与图片角色；不进入最终正文 |
| `title-options.md` | 必须 | 至少 5 个候选标题、点击理由、风险评估与锁定标题 |
| `digest.md` | 必须 | 1–2 句、15–20 字且不超过 25 字的钩子摘要（传给草稿箱 API） |
| `article.md` | 必须 | **唯一正文源**；配图采用本地相对路径（如 `images/01.png` 或 `图片/01.png`） |
| `review.md` | 必须 | 22 项 AI 味指纹、事实核验、反洗稿重合率（< 30%）检查记录 |
| `structure-check.json` / `structure-check.md` | 必须 | 字数、章节、段落、加粗、必写事实、多源覆盖及图片数量/去重/间隔/清单的机器门禁结果；未通过则不得排版或投递 |
| `转发词.md` | 完整写稿必需 | 严格遵循 Profile 的单套固定 5 段式槽位替换，不擅自发挥 |
| `wechat-body.md` | 排版/推草稿时必需 | 包含开场组件的公众号正文输入稿 |
| `layout-checklist.md` | 排版时必需 | 炭黑商务样式与草稿预览验收记录 |
| `wechat-draft.json` | 微信草稿箱推送后生成 | 包含草稿 `media_id`、核验状态与交付时间的回执文件 |
| `images/cover-900x383.png` | 有生图能力时生成 | 900×383 黑底白线视觉隐喻封面大图 |
| `images/cover-prompt.md` | 必须 | 标准化封面提示词，供 GPT、Midjourney、Ideogram 等工具接力生图 |
| `images/manifest.md` | 有正文图时必需 | 清洗后的证据图清单（序号、来源、用途、文件哈希）；正文图不可重复 |
| `adaptation.md` | 二创任务必需 | 原文来源、立论乘法、全新角度、重构时间链 |

## 图片与交付规则说明

1. **本地图片优先**：
   - 写作与审查期间，正文图片统一使用本地相对路径（如 `![说明](images/01.png)`），便于在本地 Markdown 编辑器或 Obsidian 中实时图文对照。
2. **自动化微信 CDN 托管**：
   - 当调用 `scripts/wechat_draft.py` 推送至草稿箱时，脚本会自动读取本地图片文件，调用微信官方 `/media/uploadimg` 接口直接上传并替换为微信官方 CDN 链接，无需配置或依赖外部第三方图床。
3. **禁止行为**：
   - 禁止在正文中使用超大 Base64 Data URI。
   - 禁止在终审确认前私自将草稿直接发布或群发（本系统终点严格为草稿箱）。
