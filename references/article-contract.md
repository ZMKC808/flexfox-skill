# 长文结构合同

本合同适用于默认的 AI飞升录深度长文；用户明确要求快讯、短稿或其他体裁时，才可改写数值，并把例外写入 `brief.md`。

## 成稿硬门槛

- 正文有效汉字：2,200–3,000。统计时不含 YAML、一级标题和图片 Markdown。
- 二级小标题：3–5 个 `## `。标题移除空格后按汉字、英文和数字计数，长度为 4–6；必须是能说明下文事实或动作的大白话，不能是空泛悬念。
- 小节：每个二级标题下有 3–5 个正文段落；图片不计入段落。
- 加粗：2–4 处，只给已核验的核心反转、数据或判断。
- 首段：三句内进入具体事件、数字或矛盾；不以时代背景热身。

## 图片计划

- 2,200–3,000 字的深度长文默认使用 **6–8 张正文图**；教程/实测可提高到 7–10 张。素材不足时，在 `brief.md` 说明原因，不能用广告图、口号图或重复图硬凑。
- 每张图必须是事实证据、关键 UI、操作步骤、数据图或现场画面，并在前后正文承担明确叙事作用；封面不计入正文图。
- 同一张图（相同本地文件、远程 URL 或内容哈希）只能插入一次；图片之间至少隔一个正文段落，不能连续堆叠。
- `outline.md` 需为每节标注准备使用的图片和它证明的事实；`images/manifest.md` 记录来源、用途与本地文件哈希。

## 大纲先行

正文前先创建仅供生产使用的 `outline.md`。每节至少写：

```md
## 现场当场翻车
- 证据：[S01] [S02]
- 关键事实：E01 E04
- 展开：现场摩擦 → 参数/价格 → 对读者的实际影响
- 段落预算：4
- 配图：`images/02-现场.png`（证明现场线程卡住）
```

时间、场景和镜头切换只能在事实需要时使用，不能要求每段以时间戳开头。时间推进是叙事工具，不是文章骨架。

## 生产门禁

初稿后必须运行：

```bash
python3 scripts/validate_article.py \
  --article articles/YYYY-MM-DD-主题/article.md \
  --sources articles/YYYY-MM-DD-主题/sources/index.json
```

脚本会生成 `structure-check.json` 和 `structure-check.md`。只有状态为 `pass`，才能进入 `flexfox-ai-check`、排版和草稿箱。失败时只按报告修复缺失章节或重建大纲；连续两次失败，停止自动推进并请求人工决定。
