# 长文结构合同

本合同适用于默认的 AI飞升录深度长文；用户明确要求快讯、短稿或其他体裁时，才可改写数值，并把例外写入 `过程/brief.md`。

## 成稿硬门槛

- 正文有效汉字：2,200–3,000。统计时不含 YAML、一级标题和图片 Markdown。
- 二级小标题：3–5 个 `## `。标题移除空格后按汉字、英文和数字计数，长度为 4–6；必须是能说明下文事实或动作的大白话，不能是空泛悬念。
- 小节：每个二级标题下有 3–5 个正文**语义块**；图片不计入。语义块由一个空行分隔，块内可按节奏写 1–3 句并使用自然换行；不规定一句一行、块内行数或单行字数。
- 加粗：2–4 处，只给已核验的核心反转、数据或判断。
- 首段：三句内进入具体事件、数字或矛盾；不以时代背景热身。

## 图片计划

- 2,200–3,000 字的深度长文默认使用 **6–8 张正文图**；教程/实测可提高到 7–10 张。素材不足时，在 `过程/brief.md` 说明原因，不能用广告图、口号图或重复图硬凑。
- 每张图必须是事实证据、关键 UI、操作步骤、数据图或现场画面，并在前后正文承担明确叙事作用；封面不计入正文图。
- 同一张图（相同本地文件、远程 URL 或内容哈希）只能插入一次；图片之间至少隔一个正文段落，不能连续堆叠。
- `过程/outline.md` 需为每节标注准备使用的图片和它证明的事实；`images/manifest.md` 记录来源、用途与本地文件哈希。

## 大纲先行

正文前先创建仅供生产使用的 `过程/outline.md`。每节至少写：

```md
## 现场当场翻车
- 证据：[S01] [S02]
- 关键事实：E01 E04
- 展开：现场摩擦 → 参数/价格 → 对读者的实际影响
- 段落预算：4
- 配图：`images/02-现场.png`（证明现场线程卡住）
```

时间、场景和镜头切换只能在事实需要时使用，不能要求每段以时间戳开头。时间推进是叙事工具，不是文章骨架。

## 生产门禁

初稿后必须运行：

```bash
python3 scripts/validate_article.py \
  --article 文章/YYYY-MM-DD-主题/article.md \
  --sources 文章/YYYY-MM-DD-主题/过程/来源/index.json
```

脚本会生成 `过程/structure-check.json` 和 `过程/structure-check.md`。只有状态为 `pass`，才能进入 `flexfox-ai-check`、排版和草稿箱。失败时只按报告修复缺失章节或重建大纲；连续两次失败，停止自动推进并请求人工决定。


## 用户明确要求瀑布流时的段落例外

用户明确要求短句短段、瀑布流时，显示段落可以拆开，不得为了每节3–5块的默认预算压成长段。先在本篇 `过程/brief.md` 记录用户原话及确认依据，再用 `过程/structure-policy.json` 记录 `min_paragraphs`、`max_paragraphs` 与非空 `reason`；支持范围为1–40。未配置时仍执行默认3–5。该例外只调整段落显示数量，不豁免事实、字数、审稿、图片或哈希检查。

用户明确要求逐项分节的合集时，在本篇 Brief 记录确认依据，并在同一 policy 文件配置 `min_sections` / `max_sections`（1–20）；未配置仍为3–5节。经用户确认的短稿篇幅可用 `min_han` / `max_han` 记录。例外只作用于该篇，不改变其他文章的默认门槛，也不豁免证据、独立审稿与版本哈希。


结构例外应在写作前按用户任务确定。若删冗余造成篇幅变化，应先核对是否仍符合用户确认的体裁与内容预算；不可仅为让门禁变绿而下调字数、段落或图片门槛。
