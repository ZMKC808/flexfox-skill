# 从旧 SOP 迁移

目标不是把旧工作区原样搬进仓库，而是把仍有价值的账号知识放入对应的可替换接口。

| 旧工作区内容 | 新系统位置 | 迁移原则 |
| --- | --- | --- |
| `系统/立场卡.md`、固定 CTA、开场与视觉偏好 | `flexfox-profile.md` | 提炼为账号配置，不复制旧流程说明。 |
| `资料库/Style/` 的规律与人工修改经验 | `flexfox-profile-private/style-guide.md` | 写可执行规律；现行事实红线优先。 |
| 自己认可的历史成稿 | `flexfox-profile-private/corpus/` | 常用区只选 5–10 篇黄金样本；完整历史库可留作本机归档，但每篇写作只取相近的 2–3 篇。 |
| 旧版工作流、检查表、模板 | 对照现有 `skills/` 与 `references/` | 只迁移新系统缺少的规则；同义规则不重复抄入。 |
| 微信 AppID、Secret、作者、首屏 GIF | `config/wechat.local.env` | 本地私密配置，绝不提交。 |

不要迁移旧文章的 `过程/`、抓取来源、第三方图片、历史草稿、旧脚本和密钥。它们是当时的生产痕迹，不是可复用能力；需要复盘时仍留在原工作区即可。完整历史正文若保留，也只作为本机私有归档，不进入 Git、也不在每次写稿时整库加载。

迁移后用一篇新稿验证：Profile 生效、按体裁读取 2–3 个样本、证据归属正确、`pipeline.py preflight` 通过。若某条旧规则只能解释一次历史稿，或与当前事实/审稿红线冲突，就不要迁移。
